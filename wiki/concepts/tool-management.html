工具比較與工程環境選擇

在同一項任務上比較（文件查閱 2026-11-21）

先固定需求、模型配置與驗收條件，再觀察工具入口和工程管理負擔。下表是官方文件核對 【公開技術文件】，未進行產品效能實測。

工作介面 人如何操作與查證 比較時須記錄的條件
VS Code 主視窗＋Codex extension 開發者在編輯器內選取程式、修改並與 Agent 協作。OpenAI 擴充的 session 留在主視窗。 Agents Window 的實驗性 Codex harness 是另一種入口。記錄使用哪一種。（P06）
VS Code Agents Window 並列管理 session，在 Files／Changes／Browser 查看目前工作區，可選 Branch 或 New Worktree；整合後仍須重測。 記錄 active session、harness、權限。Dev Container 不提供 New Worktree。（P06）
Antigravity Editor／Manager Google 發表時的 Editor View 供同步編輯；Manager Surface 可在多個工作區非同步指派與觀察，利用計畫、截圖或錄影審查產物。 現行 App／IDE 與發表時名稱應分別標示；模型清單含非 Gemini 選項，須核對方案。（P08、P10）
ChatGPT／Codex 桌面 新版 ChatGPT 下可切換 Chat／Work，Codex 有獨立視圖及歷史；Codex app 發表文件說明按專案切換 threads、檢視 diff 與以 worktree 隔離修改。 記錄桌面版本、入口、帳戶；單看聊天視窗無法判定多任務能力。（P24、P25）
Orca 專案側欄列出 worktree，可選起始 ref，對照工作區與 Agent 活動。需要監督時用 Run／Task／Dispatch 追蹤同一項工作的不同嘗試。 側欄父子層級只影響顯示；Orchestration 文件標 Experimental。（P12、P13）

U07 【個人直接觀點】 與 U02 【歷史研究整理】 描述了人工分工、整合及對 Orca 工作區可見性的偏好；這些是個人使用條件。產品文件可核對操作入口，無客觀最佳工具或模型效能排名。

【教學編排】 用同一個修復任務記錄三組觀察：模型是否找對問題；工具能否取得檔案、終端及瀏覽器測試證據；人花多少時間定位 worktree、確認權限、追問、審 diff、整合與恢復。將平台、版本、訂閱和未開啟的功能一起記下，才可解釋成本差異。

延伸：單 Agent 開發流程、工作隔離、協調職責。
