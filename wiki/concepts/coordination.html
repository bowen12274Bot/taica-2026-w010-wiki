Coordinator、Worker 與 Integrator

定義

Coordinator 對任務拆解、委派和追蹤負責；Worker 交付指定改動；Integrator 對基線上的整合結果負責。這些責任可由同一人或 Agent 兼任。

原理與工程用途

【公開技術文件】 P13 以 Run 收集訊息，Task 記錄規格與依賴，Dispatch 識別一次嘗試。派工寫明責任、工作區、基準、產物與驗收；完成訊息應對上有效的 Task 和 Dispatch，再檢查產物。

適用條件與限制

U03、U07 【工程設計】 將角色串成工程流程。Worker 成功回報後仍可能整合失敗；Run 不會自行派工。Orca 文件標註 Experimental，尚缺個人全程自動運作 trace。

延伸閱讀

從組織初始化到下一輪需求

U07 【個人直接觀點】 將初始化與接案分開。Project 保存產品、架構與權威基線；Role 指一組責任和決策權，可跨需求重用。Task 是有目標、依賴與驗收條件的工作；Dispatch 是對該 Task 的一次派工嘗試。Session 承載互動狀態，Worktree 隔離檔案；結束 session 或保留工作目錄都不能單獨證明任務完成。

【教學編排】 第一次先定義角色、權限、工作區與整合基準。每個新需求再走一次下列循環：

  1. PROPOSED → READY：具權者確認範圍、依賴、基準與驗收；欠缺輸入時先釐清。
  2. RUNNING：登記 Task、有效 Dispatch 和責任人。遇授權或依賴阻塞轉 BLOCKED，解阻後恢復或建立新嘗試。
  3. REVIEW：Worker 交產物與測試，Integrator 在目標基線整合、記錄 commit 並重跑；失敗則退回修正。
  4. ACCEPTED → CLOSED：具權者認可結果，更新權威版本，移交未竟事項再清理工作區。收到第二項需求可沿用角色、規範與新基線；依賴或授權改變時再調整人力。Session 可復用或退出。

[P16] 【公開技術文件】 manager 可保留控制並呼叫專家；handoff 則移交本輪控制。P13 的 Run／Task／Dispatch 與上述教學狀態機分屬不同層次。多視窗並行只表明有人在執行。U03 的完整持續自主監督 【證據待補】 仍缺跨派工、阻塞、恢復到整合驗收的端到端證據。

來源：S02（來源回執）、P12、P16。
