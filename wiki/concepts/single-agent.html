單 Agent 開發流程

定義

把一次改動界定成能驗收的工作。先確認目標、允許修改的範圍、基準版本與測試方法，才讓 Coding Agent 執行。

原理與工程用途

U02 【歷史研究整理】 用 Chatbot 討論規格，U07 【個人直接觀點】 關心工程環境與責任。實作時讀專案規範、重現既有行為、修改、執行相關測試，再回報差異和未測情境。【公開技術文件】 P05、P17 提供規範與回饋機制的依據。

適用條件與限制

例如修改輸入驗證時，以既有有效輸入與新增錯誤案例共同驗收。若需要改變產品規則，留下選項並交有權者決定。U04 【工程設計】 只支持規格設計。

延伸閱讀

規格與 Harness Engineering、需求邊界與人類授權、工程品質與驗證。

來源：P05、P17、U-A（來源回執）。

選環境時可用工具比較與工程環境選擇核對工作區、瀏覽器與人工整合成本。

【教學編排】 對照操作案例：用同一項修復比較工作環境。
