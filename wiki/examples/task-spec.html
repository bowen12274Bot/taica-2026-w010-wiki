工作票：契約、API、畫面與整合

合成情境，供練習工程判斷。

【合成教學案例】 每列是一張可複製的票；表中提交與結果欄請執行者實填。

票／Target Change／Constraints Owner／工作區／Base Dependencies Output Acceptance
F0 凍結單標籤契約 定義省略與無匹配；不開多選 人類核准、Coordinator 整理／規格區／B0 需求一 介面例與 fixture A/B 核准三個輸入輸出
F1 API 篩選 GET /todos 加單值匹配；維持原列表順序 API Worker／wt-api／B0＋F0 契約 F0 API diff、commit、測試輸出 work→A，missing→空，省略→A/B
F2 UI 操作 選取與清除；不得改 API 規則 UI Worker／wt-ui／B0＋F0 契約 F0 畫面 diff、模擬回應與操作紀錄 確認參數、結果及清除；標示 mock 範圍
F3 整合交付 套入雙方變更，重跑真 API/UI；不得自行裁決歧義 Integrator／wt-int／B0 F1＋F2 整合提交、回歸、未測清單 授權者核對三個案例後才登記 B1

F1/F2 可並行的前提是同一版 fixture。若兩者都要改同一型別，先回 F0 協調；重派沿用票號，另記派工嘗試。
