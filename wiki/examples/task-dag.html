依賴圖：哪些工作可以先開始？

合成情境，供練習工程判斷。

【合成教學案例】 箭頭代表下游需讀到上游交付物。兩個 Worker 開著視窗並不會解除任何一條依賴。

B0 → 需求一 → F0（核准契約）┬→ F1（API）┐
                          └→ F2（UI） ┴→ F3（基線整合）→ 接受 B1
待決 → BLOCKED → 裁決 → 回原票；測試失敗 → 修責任票 → 再驗 F3
B1 → 需求二（多標籤）→ 新契約 → 新工作票

人工派工：依 F0 核准記錄，分別把票與工作區交給執行者。Coordinator 派工：掃描前置均完成的票 → 核對所有者及授權 → 記錄有效 Dispatch → 收件與檢查產物 → 更新狀態。兩條路都要等 F3，且只有具權者能採納新基線。若 F2 只交 mock 結果，F3 必須跑真實資料路徑。

教學入口：T05、T06、T08。
