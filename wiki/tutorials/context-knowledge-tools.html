T02｜把正確的規格帶進本輪 Context

學習問題與先備

【教學編排】 懂得模型只看到本輪輸入。接手另一個人的篩選任務，先找出現行契約，再決定怎樣查它。

技術與方法依據

【公開技術文件】 P30：檢索系統以問題為輸入，選出有權讀取的相關片段供生成使用。P04 描述 Skill 的發現及載入，P03 描述 MCP client 與 server 的工具或資源；P05 讓專案指引有可預期的位置。

操作順序與資料流

【合成教學案例】 提問「未帶 tag？」→ 限定本專案與可讀版本 → 搜尋介面文件 → 核對版本與段落 → 將短摘錄及定位加入 Context → 依契約回答。沒有相關段落就標待決。

  1. 【合成教學案例】 先讀 repo 的 AGENTS.md，取得工作範圍與測試命令；把 B0 和有效 Task 寫成當輪輸入，以免採用舊草稿。

  2. 【合成教學案例】 若文件很多，用 RAG 找候選段落，再用 Project State 所列核准版本查驗。若只有一份短文件，可直接讀檔，省去檢索步驟。

  3. 【合成教學案例】 需要一致的瀏覽器驗收步驟時才載入 Skill；需要跨工具讀取記錄時才透過已授權 MCP 資源。沒有 MCP 時，本機測試和人工查閱也能交付證據。

  4. 【合成教學案例】 換 session 時從共享狀態重新組 Context。Memory 可保存跨任務的知識；Project State 表示當前權威基準及決策；Task State 表示本票的嘗試與阻塞。

適用範圍與反例

【工程設計】 S03 的分層摘要需保留原件位置。檢索命中舊版「空字串代表全部」時，不能把相似度當成核准紀錄。

自我驗收

【教學編排】 同時找到過期草案和現行規格，哪個片段應送進模型？

判斷依據：查版本、批准人及適用範圍；若無法確認，保留衝突交裁決。Skill 可指導如何查，工具授權須獨立核對。
