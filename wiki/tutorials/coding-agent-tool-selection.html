T03｜用同一項修復比較工作環境

學習問題與先備

【教學編排】 認識檔案與 Git 差異。要比較哪種入口便於定位篩選錯誤，先固定同一基準、需求及驗收。

技術與方法依據

【公開技術文件】 產品入口按本地摘要查閱 2026-11-21；瀏覽器文件 P07 於 2026-11-22 查核。VS Code 主視窗的 Codex 擴充配合直接編輯；Agents Window 依 session 查看 Files、Changes、Browser，可按條件開 New Worktree；Dev Container 有限制。

操作順序與資料流

【合成教學案例】 比較表欄位：入口／平台／harness／權限 → 目前 repo、branch、worktree → 如何看 diff 與工具輸出 → 整合方式 → 人工追問或切換次數。欄位未知填未測。

  1. 【合成教學案例】 需要人機同步看程式時，試用 VS Code 主視窗或 Antigravity Editor。需要非同步觀察數個工作區時，查 Agents Window 的 session 或 Google 發表時的 Manager Surface 與 Artifacts。核對模型及方案，不用介面名稱推定模型能力。

  2. 【合成教學案例】 桌面環境先分辨 ChatGPT 的 Chat／Work 與獨立 Codex 視圖；Codex app 有專案 threads、diff 與 worktree。Orca 可從專案側欄辨認 worktree 與 Agent，持續監督另需核對實驗性 Orchestration。

  3. 【合成教學案例】 每個入口各走一次相同演練：尋找 UI 檔、確認 Shell 的 cwd 與 branch、讀 diff，依專案命令啟動測試。用 Browser 點選 work，查 Console 例外、Network 請求與回應、擷取畫面並比對 fixture。缺少 Network 工具時改由獲准的人員看 DevTools 或服務記錄。

  4. 【合成教學案例】 記錄開工作區、看產物、恢復中斷及確認整合的人工作業；不同模型、登入或權限須分欄，無法控制的條件保留未知。

適用範圍與反例

【個人直接觀點】 U07／S01 描述使用者偏好 Orca 的專案可見性；【證據待補】 沒有固定版本、同任務跨工具跑分。

自我驗收

【教學編排】 若 A 的截圖正確、B 的工具能顯示 HTTP 回應，哪一個已證明篩選正確？

判斷依據：兩者各有觀察邊界；先確認請求、fixture 與顯示結果一致，再談維護和人工監督成本。
