T08｜失聯的工作票如何安全接手

學習問題與先備

【教學編排】 能讀 Task、Dispatch 與版本定位。你收到一則「還沒好」；先問是哪次嘗試、最後確認了什麼。

技術與方法依據

【個人直接觀點】 U07 描述等待、改做獨立工作、跨專案或介入；【公開技術文件】 P13 提供可追蹤的派工及回報，P28 的 trace 可追查執行事件。

操作順序與資料流

【合成教學案例】 狀態不明 → 核對有效 Dispatch、最近回報與產物 → 有阻塞則標記原因／責任人 → 解除、換獨立票或升級 → 確認原嘗試狀態後才接手。

  1. 【合成教學案例】 F2 等規格時，查 Project State 的核准版本、Task State 的前置票、Trace 的最後事件；Memory 有舊設計，Context 只是會話當輪所見，兩者都不能推翻專案基線。

  2. 【合成教學案例】 若負責人仍在核對且無獨立工作，可等候並約定下次檢查事件。若其他票只依賴 B0，可切換；若只有草案，先列測例但標假設。轉做其他專案前先留狀態、查授權與切換成本。

  3. 【合成教學案例】 若卡在決策權或重複嘗試無新觀察，Coordinator 彙整替代案請人裁決。失聯時查分支與最後輸出，確認所有權再重派，避免兩次嘗試同寫。

  4. 【合成教學案例】 Worker 交 base/diff/已測與未測；Coordinator 向上送風險與待決；Integrator 查合併後 commit 及回歸；Human 按目標批准或退回。每層摘要附原始位置與有效嘗試。

適用範圍與反例

【證據待補】 沒有跨專案切換最優時間或固定逾時門檻；等待長度須配合依賴及風險。

自我驗收

【教學編排】 只有十分鐘沒有訊息，是否重開同票？

判斷依據：先區分無心跳、已故障與等待批准。確認舊嘗試狀態、可恢復證據及所有權，再決定是否重派。
